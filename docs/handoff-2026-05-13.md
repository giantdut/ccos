## Current architecture

See `CONTEXT.md` for the full domain glossary and `docs/adr/` for the 9 ADRs that govern the architectural spine.

### DB schema (`src/lib/db.ts`)

Tables (all SQLite via `better-sqlite3`):

- `jobs` — background job rows (status, input, output, error)
- `job_events` — SSE event log per job
- `knowledge_uploads` — Operator-uploaded documents
- `planning_sessions` — topic + source toggles + job reference
- `research_bundles` — JSON research output keyed by session
- `content_schedules` — proposed → approved lifecycle
- `schedule_items` — items within a schedule (title, publish_date, outline)
- `tasks` — one per approved schedule item; status: `pending → drafting → in-review → approved`
- `drafts` — expanded_outline, agent_draft (immutable), draft_content (editable), edit_distance, status
- `signals` — operational events (type, payload JSON, created_at)

## What's NOT done / known gaps

1. **No Operator authentication** — basic-auth is handled at the Caddy proxy layer (see `Caddyfile`, ADR-0008), not in the app. The `/signals` Owner dashboard has no additional access guard; the proxy must enforce it.

2. **No re-run UI for interrupted drafts** — `markInterruptedDrafts()` marks them on restart but there's no UI button to re-trigger the pipeline. The task detail page shows an "interrupted" message but no action.

3. **No schedule-item delete UI** — The `DELETE /api/content-schedules/[id]/items/[itemId]` endpoint exists and records a signal, but the schedule detail page has no delete button on items.

4. **No "draft reject" UI surface** — `POST /api/tasks/[id]/reject` exists but the task page only has an Approve button; a Reject button (or flow) is not wired.

5. **Planning session: extend vs. new schedule** — The domain model says the Operator can extend an existing schedule at session start. The current API creates a new schedule every time.

6. **Twitter/X, LinkedIn, TikTok, Instagram** deferred from v1 per `CONTEXT.md`.

## Dev / deploy notes

- **Run locally:** `npm run dev` (requires `ANTHROPIC_API_KEY` in `.env`)
- **Container:** `docker-compose up` — Caddy proxies port 80 → Next.js; DB persists at `/data/ccos.db`
- **Tests:** `npm test` (Vitest, in-memory SQLite, no API keys needed)
- **DB path:** `DATABASE_URL` env var or `./ccos.db` in cwd
